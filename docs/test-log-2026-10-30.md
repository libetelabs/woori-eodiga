## 찾아서 고친 버그

1. **앱 시작 ANR** — 차량 서비스·내비가 바쁘면 `Car.getCarManager` / `NaviHelper.initialize` 가 20초 넘게 걸렸다.
   메인 스레드(Application.onCreate)에서 부르고 있어 "failed to complete startup" ANR 로 죽었다.
   ANR 기록(`dumpsys dropbox --print data_app_anr`)에서 `woori-gear` 스레드가 Car 내부 잠금을 쥔 채 바인더 응답을 기다리고,
   메인이 같은 잠금을 기다리는 것을 확인. → Car 는 생성부터 구독까지 전용 스레드, NaviHelper 는 전용 HandlerThread 에서만 부른다.
   Application.onCreate 7ms 로 줄었다.
2. **밤에 도착 카드 글씨가 안 보임** — 카드 그림은 밤에도 밝은 종이색인데 글씨가 밤 토큰(밝은색)을 따라갔다. → `card_text` 고정색.
3. **낮은 화면에서 "여행 끝내기"가 밀려남** — 카드가 그림 비율대로 커졌다. → 카드는 남는 높이만(weight 1).
4. **이름 없는 바로가기 버튼** — 내비 최근 목적지에 이름이 빈 항목이 섞여 빈 버튼이 됐다. → 이름이 없으면 주소, 둘 다 없으면 뺀다.
5. **데모 재시작** — 밀도 변경으로 화면이 다시 만들어질 때 처음 intent 의 `demo=true` 로 데모가 또 시작됐다.
   → `savedInstanceState == null` 일 때만.

## 알아낸 사실

- **이미지는 user 빌드.** `cmd car_service inject-vhal-event` / `get-property-value` 는 "requires non-user build" 로 막힌다.
- **기어는 Virtual Console HTTP.** `adb forward tcp:8088 tcp:8088` 후 `PUT /vehicle/gear?gear=Drive|Park`.
  콘솔 페이지가 브라우저에 열려 있어야 먹는다(안 열려 있으면 `{"error":"emulator_inactive"}`). 페이지를 열면 기어가 P 로 초기화된다.
  콘솔 → `SDV_MOTION_GEAR` → `sdv_vhal` → AAOS `GEAR_SELECTION` 으로 이어져 앱의 CarPropertyManager 가 그대로 받는다.
  그 밖의 HTTP: `/vehicle/state`, `/vehicle/controls`(속도·페달·조향), `/vehicle/body`, `/vehicle/hvac`, `/vehicle/etcs`, `/vehicle/catalog`.
- **음성.** Pleos 이미지엔 안드로이드 기본 TTS 엔진이 없다(`tts_default_synth` 없음, `onInit status=-1`).
  Pleos TextToSpeech 3.3.1 로 바꿨다. 결론: **ON_DEVICE + `Locale.KOREA`(ko_KR)** 로 소리가 난다.
  - 처음 ON_DEVICE 요청 땐 기기 안 모델 파일(`.../airspeech/TextToSpeechConfig.dat`)이 없어 `ON_DEVICE_ENGINE_ERROR`.
    이때 서비스가 모델 제공 앱(`ai.pleos.gleoai.model.provider`)에 신호를 보내고, 몇 분 뒤 다시 요청하니 모델이 있었다.
  - 언어를 `Locale.KOREAN`("ko")으로 주면 엔진이 `unsupported locale: ko-` 로 실패. `ko_KR` 이어야 한다(Pleos 앰비언트 AI 도 ko_KR).
  - 서버 합성(HYBRID/SERVER): Pleos Playground My Project「우리 어디가?」(카테고리 키즈)를 만들어
    Client ID·Secret 을 받아 `local.properties` 에 넣었다(레포 제외). `registerApp` 은 연결되지만 합성 요청은 **HTTP 401**.
    My Project > SDK 에서 TextToSpeech 가 **"준비 중"** 이라 신청 자체가 안 된다. HYBRID 는 401 뒤 기기 안으로 넘어가 1초쯤 늦으므로
    `Voice.SERVER_TTS_OPEN = false` 로 꺼 두었다. Pleos 가 신청을 열고 승인되면 true 로.
  - SDK 순서 주의: `initialize` 가 끝나기 전에 `addEventListener` 를 부르면 SDK 안에서 `lateinit property tts` 로 죽는다.
  - SDK 를 넣으니 APK 가 7MB → 27MB.
- **부팅 직후** 홈이 기본 내비(`ai.umos.maps.android.navigation.app`)를 앞으로 띄워 우리 앱이 가려진다. 1~2분 기다리거나 앱을 다시 앞으로.
- 다른 세션이 다른 버전의 adb 를 쓰면 adb 서버가 갑자기 재시작되며 `device offline` 이 난다(설치가 조용히 안 될 수 있으니 결과의 Success 를 꼭 볼 것).
- 기본 내비는 에뮬레이터에서 CPU 를 상시 50% 안팎 쓴다. 맥에 다른 무거운 작업(브라우저 E2E 등)이 같이 돌면 차량 서비스·내비 응답이 수십 초로 늘어난다.
- Pleos 키보드 앱(`ai.umos.inputmethod`)이 한 번 죽은 기록이 있다(우리 앱과 무관).

## 밤에 추가: Pleos 디자인 가이드 맞추기

- Pleos 는 안드로이드 UI 코드 라이브러리를 주지 않는다(메이븐엔 기능 SDK 만). 가이드 그림(SVG)을 그려 수치를 쟀다.
  - Basic Button: Large 높이 100·모서리 약 32 / Medium 80·24 / Small 64·16. Primary=옅은 회색(#F3F3F3) 검은 글씨, Secondary=진회색(#44464E) 흰 글씨.
  - Toggle Button: 평소 옅은 회색, 고르면 흰 바탕+그림자(Floating). 모서리 약 24, 높이 80.
  - 글자: Headline 60/56/48(줄 80/72/64), Title 40/36/32(52/44/40), Body 30/28/26(38/36/34), Label 24/20(28/24). 최소 12sp.
- Pleos 이미지는 시스템 sans-serif 를 **Asta Sans** 로 바꿔 두었다(`/product/etc/fonts_customization.xml`). 앱 글씨는 따로 안 넣어도 Asta Sans.
  단 굵기 700 은 ExtraBold 파일로 가서 너무 두껍다 → Bold 는 600 으로.
- 적용: 버튼=Basic Button Large(보통은 Primary, 화면마다 하나인 주 버튼만 앱 보라), 목적지·탈것 고르기=Toggle Button, 글자 크기·줄 높이=가이드 단계.
  캡처: `17-pleos-buttons-home.png`, `18-pleos-buttons-daynight.png`. 토글 버튼 캡처는 아래 기어 문제로 내일.
- 버그: 차량 서비스가 바쁘면 `Car.createCar` 가 5초 뒤 null → 그 뒤로 기어를 못 읽었다. 3초 간격 20번 다시 시도하도록 고침.
