## 창 크기 시험(FormFactorConsole)

- FormFactorConsole 은 에뮬레이터 안의 앱이다: `ai.pleos.connectwebconsole/.FormFactorConsoleActivity`.
  화면은 웹 콘솔(`/form-factor-console`, 8095)이고, 맥에서 `connect-display-bridge --avd Pleos_Connect_v2_1` 을 띄워야 DISPLAY2 를 만들 수 있다.
- 프리셋마다 "앱 창 크기"(dp)가 정해져 있다(콘솔 `window-policy.js`).

| 프리셋 | 가로 | 세로 |
|---|---|---|
| Connect-S 17″ (160dpi) | 1700×1184 | 840×1184 |
| Connect-S 14.6″ (200dpi) | 1360×948 | 672×948 |
| Connect-S 12.9″ (160dpi) | 1274×855 | 628×855 |
| Connect-WS 24.6″ | 1640×810 | 800×810 |
| Connect-WE 24.6″ | 1640×1400 | 800×1400 |
| Connect-WF 18.7″ (200dpi) | 1256×800 | 648×800 |

- 자동 시험: `ADB=… bash tools/formfactor.sh` → 12가지를 차례로 만들어 앱을 띄우고 `tools/out/ff/` 에 캡처.
  화면 캡처는 `adb emu screenrecord screenshot <폴더> --display 2`(가상 디스플레이는 `screencap -d` 로 안 찍힌다).
  디스플레이를 다시 만들면 번호가 바뀌어 `dumpsys display` 에서 "Emulator 2D Display" 번호를 찾아 `am start --display` 한다.
- **버그: 세로 창에서 주 버튼이 밀려남.** 그림이 높이의 절반 넘게 차지해 12.9″·WS·WF 세로에선 "얼마나 남았어?"가 화면 밖, 14.6″ 세로에선 반만 보였다.
  주행 중에 스크롤을 시키면 안 되므로 → 세로 창은 패널에 필요한 높이(여행 540dp, 도착 420dp)를 먼저 주고 남는 만큼만 그림에 준다(최소 200dp). 고친 뒤 12가지 모두 버튼이 보인다.

## 알아낸 사실

- 실제 차에서 시험하는 공식 경로는 없다. 차에는 App Market 심사를 통과한 앱만 깔린다. 공모전은 1차 기획서만 필수, 시연 영상(에뮬레이터 녹화 인정)·GitHub·APK 는 가산점, 본선은 현대차가 최종 APK 로 구동 시험.
- 플레오스 차에는 유튜브 앱이 따로 있다(앱마켓, 스마트폰 연결 없이). 우리 앱은 `ACTION_VIEW` 플레이리스트 주소로 연다.
- 에뮬레이터의 시험용 브라우저(`org.chromium.webview_shell`)는 기본 카테고리가 없어 다른 앱이 주소를 넘겨도 받지 못한다.
- 외장 SSD 를 뽑을 때 돌던 adb 서버가 커널에서 멈춘 채 남아 5037 포트를 막는다. `ANDROID_ADB_SERVER_PORT=5038` 로 새 서버를 띄우면 된다(맥 재부팅하면 사라짐).
- release 빌드 때 AGP 8.7 lint 가 새 SDK 도구 버전 문자열("37.0")을 못 읽고 죽는다 → release 빌드의 lint 만 끔.
- 에뮬레이터 안 왼쪽 주행 화면(`ai.umos.drivingview`)이 CPU 를 상시 100% 넘게 써서 부하가 7 아래로 잘 안 내려간다. 조작이 몇 초씩 늦게 먹는다.
